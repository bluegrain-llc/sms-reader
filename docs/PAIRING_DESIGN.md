# Direct app/bot connections

This supersedes the external manager design in ADMIN_RELAY_DESIGN.md. The Android application's Admin area manages callers directly. There is no manager credential or external provisioning authority.

A bot starts a connection without knowing an owner account. It gets one random 256-bit pending caller credential, a ten-character comparison code, and an HTTPS connection link. The owner opens that link on a registered phone (verified Android App Link, with browser/custom-scheme and code-entry fallbacks), reviews the named caller/purpose/expiry in Admin, and approves or declines. Only approval transactionally creates an owner-bound grant. The bot polls using its private pending credential, which becomes its own caller credential after approval. Only hashes are stored; no credential is put in the link or shown on the phone. Google sessions remain restricted to owner/phone operations.

Pending connections expire in ten minutes. Approval cannot extend or revive a pending expiry. Concurrent owners have one decision winner; retries by that owner are idempotent. Other owners cannot inspect an already claimed connection. Revocation and account deletion immediately block an approved credential. Polling is paced at five seconds. Public creation has persistent per-source and global fixed-window limits; owner code lookups/decisions are also limited. Pair metadata retains seven days; code/rate indexes are cleaned after expiry, with TTL as backstop.

Domain: a requesting app, a comparison code, an account owner, a connection decision, a caller credential, and registered phones. Colors stay in the established paper/graphite/signal/mint palette, with red for refusal/revocation. The signature is a named handoff: app asks → owner connects → future SMS still needs Android consent. Avoid master-secret dialogs, required per-bot credential copying, and generic dashboards.

Component checkpoint: the owner has just tapped a bot's link and wants to decide one connection. App name leads at 24–28sp, purpose follows, comparison code is monospace, and the account/credential expiry makes the scope explicit. Existing white Panels over paper provide tonal depth; teal denotes Connect and red/secondary denotes Decline. Keep Material 3 primitives, 4dp rhythm, 20dp panels and 12dp control groups, with 48dp controls. Admin Access shows the current review first, a compact fallback code form, then connected callers and revoke controls. Relay remains dedicated to per-message consent. The fallback web page uses the same colors/type hierarchy and one Open app link without browser-side login or scripts.

Each paired caller remains account-scoped, not phone-scoped. New SMS requests continue to notify all unpaused registered phones, with individual consent gates and first approved upload winning. Pairing never grants inbox access and never triggers SMS.
