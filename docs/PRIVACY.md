# Pilot privacy disclosure

## Interactive request inbox

Connections can additionally request information or decisions only after explicit form approval in Settings → Access. These requests process the requesting app’s Markdown message, immutable form definition, chosen action and entered values. General forms always require explicit submission, including after SMS autofill; the existing SMS-only automatic consent flow remains compatible. The full SMS is never uploaded. Answers are available only to the originating connection for 24 hours after submission. Definitions, outcomes and metadata-only events are retained for seven days after termination. Pending general requests expire after 24 hours by default, up to seven days.

The app reports notification taps and foreground rendering separately. These observations do not confirm agreement or that the whole message was read. Owner-bound background retries store observation IDs and times, never response values or SMS content. Senders may subscribe to metadata events over signed HTTPS webhooks; answers are retrieved separately. Google Cloud Tasks wakes delivery workers; scheduled maintenance recovers missed wakeups. Account deletion includes form answers, events, callback jobs and webhook signing secrets. See the [interactive-request contract](REQUEST_INBOX.md).


**Draft for a private pilot.** The operator must add its legal name, privacy contact, public policy URL, and public account-deletion request URL before distributing outside the pilot or submitting to Google Play.

SMS Code Relay lets a caller you authorize ask for one upcoming verification code. It does not read your SMS inbox. You open the request, Android listens for a new eligible message, and Android asks permission to give that message to the app. If you approve, the app extracts candidates on your phone and automatically sends a single code. Multiple candidates require you to choose which code to send. You can also enter a code manually, including after declining Android message access; manual entry requires Send. Only the code you submit is sent to the caller’s relay request.

The service processes your Google/Firebase account identity, installation ID and device name, FCM delivery token, caller labels/identifiers, connection purposes and comparison-code hashes, request title, Markdown explanation and optional expected sender, request status/timestamps, and the approved code. The full SMS is never uploaded. Google Firebase Authentication, Firestore, Cloud Messaging, and Cloud Run provide authentication, storage, notification delivery, and hosting. The approved code is disclosed only to the token that originated its request and the service infrastructure that stores/delivers it.

Approved codes stop being retrievable after two minutes and are scheduled for deletion. Firestore TTL also deletes expired documents asynchronously; physical removal can occur later than the API deadline. Request metadata and metadata-only audit events are retained for up to seven days before scheduled/TTL deletion. Account/device configuration remains until you delete it. The app has no ads, analytics, or message-content logging. Infrastructure access logs contain request route/status metadata according to the operator's Google Cloud retention settings.

In **Settings → Devices**, turn off **Receive requests** for this phone to stop its participation. Other available phones still receive requests. Requests notify every available phone registered to the same account; the first approved response completes the request. Under **Settings → Access**, revoke a caller to stop its requests and block retrieval. Removing a phone leaves account-scoped caller access and request history/results available with their normal retention. **Settings → Devices → Delete account** requires recent Google sign-in and removes all owned phones, connection records, caller grants, requests, results, audit events, and the Firebase identity. Minimal deletion markers prevent stale access and re-creation races. Deleting this app alone does not delete server data; use the in-app controls first, or the operator's account-deletion contact when published.

Android notification permission is used to alert you and reopen a pending approval. Google Play services are required for one-message SMS consent. No broad SMS, Contacts, accessibility, or default messaging permission is requested. Your current messaging app remains available.

Before Play submission, the operator must finalize public privacy/deletion URLs, review current Data safety disclosures (including account identifiers, device/installation identifiers, messages/codes processed by the service, diagnostics/access metadata, retention and deletion), document Firebase/Google Cloud service providers and hosting region, and confirm whether infrastructure backups/PITR are enabled. This document does not claim Play approval or a legal review.

App/bot connections require separate approval in Settings → Access before they can request SMS codes. The bot gets a private pending credential and a short-lived public connection link/code; its credential becomes usable only after approval. The phone never displays or copies this credential. Connection metadata retains seven days, while comparison-code/rate records expire after their short windows. Android-assisted filling still needs a separate Android consent decision for each message. Manual entry does not read the message; Android approval can send automatically, while manual entry requires Send.

Connection URLs may appear in ordinary infrastructure route logs. They contain only the short-lived comparison code, not the private caller credential or an SMS message/code.

Wizard step progress and response drafts remain only in app memory, isolated by request and signed-in owner. Previous/Next and Back to inbox retain them while the process lives; process death loses them. Only a final submission uploads answers. Hidden-branch answers are discarded when the selected path changes.
